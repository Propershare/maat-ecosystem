# Maat Framework

**Personal AI that adapts to you, learns from you, and respects boundaries.**

One command to start. One memory for all agents. One security model. Local-first.

```bash
maat start
```

---

## What Is This?

Maat is a framework for building personal AI agents that:

- **Adapt** — auto-detect what's on your system and configure themselves
- **Learn** — remember every interaction and get smarter over time
- **Guard** — enforce who can read, write, and execute via Three-Ring governance
- **Plug in** — any new tool or model drops in via MCP (Model Context Protocol)

Built on [Ollama](https://ollama.com), [PostgreSQL + pgvector](https://github.com/pgvector/pgvector), and [MCP](https://modelcontextprotocol.io).

---

## Quick Start

### Prerequisites

- Linux (Ubuntu 22.04+ recommended) or macOS
- Python 3.10+
- PostgreSQL 15+ with pgvector extension
- Ollama installed with at least one model

### Install

```bash
git clone https://github.com/tehuti-lab/maat-framework.git
cd maat-framework
pip install -e .
```

### First Run

```bash
maat setup     # Interactive: detects your system, sets up DB, downloads a model
maat start     # Starts the agent with memory, security, and tools
```

### That's It

Your agent is running. Talk to it. It remembers. It learns. It respects boundaries.

### Components

| Component | What It Does | Where It Lives |
|-----------|-------------|----------------|
| **Adapt** | Scans system, finds models/tools, generates config | `maat/adapt.py` |
| **Learn** | Logs interactions to gitMaat, retrieves context via RAG | `maat/learn.py` |
| **Guard** | Three-Ring access control on every action | `maat/guard.py` |
| **Agent** | Conversation loop, tool calling, routing | `maat/agent.py` |
| **CLI** | `maat` command — setup, start, status, learn | `maat/cli.py` |

### MCP Servers (Consolidated)

| Server | Port | What It Covers |
|--------|------|---------------|
| **maat-core** | 8014 | Shell, filesystem, gitMaat queries, code execution |
| **maat-research** | 8012 | RAG search, document ingestion, web search |
| **maat-creative** | 8019 | Image generation (ComfyUI), audio (Bark TTS) |

Three servers. That's it. Everything else merges into core.

## Configuration

After `maat setup`, your config lives in `~/.maat/config.yaml`:

```yaml
# Auto-generated by maat setup — edit freely

agent:
  name: "tehuti"                    # Your agent's name
  model: "gemma4:e4b"              # Ollama model to use
  personality: "concise and helpful"

memory:
  backend: "postgres"               # postgres or json
  database_url: "postgresql://..."  # Auto-detected from .env
  embedding_model: "nomic-embed-text"
  context_limit: 10                 # Max memory results per query

security:
  governance: "three-ring"
  default_role: "outer-ring"        # For the owner
  scan_commands: true               # Pre-exec security scanning

tools:
  mcp_servers:
    - name: "maat-core"
      url: "http://localhost:8014"
    - name: "maat-research"
      url: "http://localhost:8012"
    - name: "maat-creative"
      url: "http://localhost:8019"

ollama:
  host: "http://localhost:11434"
  models:                           # Auto-detected
    - "gemma4:e4b"
    - "maat-compact-v1"
    - "nomic-embed-text"
```

## Usage

### CLI Commands

```bash
maat setup          # Interactive first-run setup
maat start          # Start the agent (foreground)
maat start -d       # Start as daemon
maat stop           # Stop the daemon
maat status         # Show what's running
maat chat "hello"   # One-shot message
maat learn          # Run the learning cycle (generate training data from logs)
maat learn --train  # Generate training data AND fine-tune
maat adapt          # Re-scan system and update config
maat guard --check  # Audit current security posture
```

### Python API

```python
from maat import Agent

agent = Agent()  # Loads config from ~/.maat/config.yaml
response = agent.chat("What did we decide about auth last week?")
# Agent queries gitMaat, finds relevant memory, responds with context
```

### As a Library (for other agents)

```python
from maat.learn import query_memory, log_task
from maat.guard import check_access

# Any agent can use these
results = query_memory("recent decisions about deployment")
log_task("deployed v2.1 to production", agent="my-custom-agent")
allowed = check_access(agent="my-custom-agent", action="execute", resource="/bin/rm")
```

## How Learning Works

```
1. You talk to the agent
2. Every interaction → logged to gitMaat (Postgres + embeddings)
3. Next conversation → agent queries gitMaat for relevant context
4. Context injected into prompt → agent responds with memory
5. (Optional) Weekly: maat learn --train
   → Extracts quality interactions
   → Generates LoRA training pairs
   → Fine-tunes base model
   → Deploys updated model to Ollama
```

**Important:** Step 5 is optional. Steps 1-4 give you 90% of the "learning" effect through RAG. Fine-tuning is for when you want to teach the model new behaviors, not just new facts.

## How Security Works

### Three-Ring Governance

```
┌──────────────────────────────────┐
│         OUTER RING               │
│   Full access: read/write/exec   │
│   Who: owner, admin agents       │
│                                  │
│   ┌──────────────────────────┐   │
│   │      MIDDLE RING         │   │
│   │   Read + propose changes │   │
│   │   Who: trusted agents    │   │
│   │                          │   │
│   │   ┌──────────────────┐   │   │
│   │   │   INNER RING     │   │   │
│   │   │   Read only      │   │   │
│   │   │   Who: guests,   │   │   │
│   │   │   public agents  │   │   │
│   │   └──────────────────┘   │   │
│   └──────────────────────────┘   │
└──────────────────────────────────┘
```

Every agent action passes through the guard:

```python
# Automatic — you don't call this manually
guard.check(agent="some-agent", action="execute", resource="rm -rf /tmp/cache")
# → Returns: allowed=True/False, reason="...", ring="outer"
```

### Command Scanning

Before any shell command executes, it's scanned for:
- Dangerous patterns (rm -rf, chmod 777, etc.)
- Injection attempts
- Exfiltration attempts (curl/wget with secrets)
- Homograph URLs

## Adding Tools (Plug & Play)

### Option 1: MCP Server

Any MCP-compatible server works. Add it to config:

```yaml
tools:
  mcp_servers:
    - name: "my-new-tool"
      url: "http://localhost:9000"
```

Run `maat adapt` and the agent discovers the new tools automatically.

### Option 2: Python Function

```python
# ~/.maat/tools/my_tool.py
from maat.tools import tool

@tool(description="Search my notes for a topic")
def search_notes(query: str, limit: int = 5) -> str:
    # Your implementation
    results = my_notes_db.search(query, limit)
    return format_results(results)
```

Drop it in `~/.maat/tools/` and restart. Done.

## FAQ

**Q: Do I need a GPU?**
A: No. Ollama runs on CPU. A GPU makes it faster but isn't required.

**Q: Can I use cloud models (GPT-4, Claude) instead of local?**
A: Yes. Set `agent.model` to any OpenAI-compatible endpoint. But the point is local-first sovereignty.

**Q: How is this different from LangChain / CrewAI / AutoGen?**
A: Those are libraries for building agents. Maat is a complete personal agent that works out of the box. It adapts to YOUR system, learns from YOUR interactions, and enforces YOUR security rules.

**Q: Can multiple users share one instance?**
A: Yes. Three-Ring governance controls who can do what. Each user gets their own LDAP role and memory namespace.
